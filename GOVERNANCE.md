# Governance

tmuxes is currently maintainer-led.

## Decision Making

Maintainers make final decisions on product direction, architecture, releases,
and security handling. Technical decisions should be grounded in reproducible
bugs, real user workflows, code evidence, tests, and maintainability.

## Contribution Model

The project accepts issues and pull requests from the community. Maintainers
may ask contributors to narrow a change, add tests, rewrite an implementation,
or move design discussion to an issue before review continues.

## Maintainer Responsibilities

- Keep the main branch buildable.
- Protect release signing material and user security.
- Review security reports privately.
- Keep contribution expectations clear.
- Avoid accepting broad rewrites without evidence and validation.

## Becoming A Maintainer

The project will consider adding maintainers after sustained, high-quality
contributions in code review, issue triage, documentation, testing, or release
work.
